**Verdict: GO, conditional on six plan amendments being written before coding.** The architecture is right. No new process, broker or engine is proposed, and the four places where Erlang currently interprets door state (`install_controls`, `sample_doors`, `activity/1`, `physics_sample_fence`) do become generic under the plan. The blockers below are contract gaps that would ship wrong physics or wedged custody, not architectural problems. No implementation exists, so nothing is verified green. I could not check Rapier 0.36 internals, the client sources, or the ontology bundling loader; none are in the packet.

## Prioritized findings and necessary plan changes

**P1. Joint frames are under-specified, and the "deterministic axis-frame construction" claim is untested in this tree.** The in-tree native never derives a frame from an authored axis. It hardcodes `Vector::Y` for both bodies and places the leaf from the box half-width (`tree/native/quod_physics/src/lib.rs:283-295`). A revolute angle is measured between two full frames, not two axes. If each frame is derived from the authored axis by a rotation-from-X, then angle zero is implementation-chosen whenever `FixedAxis` differs from `MovingAxis`, and an axis antiparallel to X is a known degenerate input (nalgebra returns none, glam picks an arbitrary perpendicular). Required change: native builds both frames with its own stated total function (normalized axis plus a deterministic perpendicular rule), sets both local frames directly, and restores the moving pose as `R_m = R_f·F1·Rot(θ)·F2⁻¹`, `p_m = p_f + R_f·a1 − R_m·a2`. For this slice, require the two authored axes to be the same local vector and define angle zero as "moving frame aligned with fixed frame through the anchors"; reject anything else. Native tests must cover ±X, ±Y, ±Z and one oblique axis, asserting the sampled angle at restore equals the restore angle and that a positive target rotates right-handed about the authored axis. The single-turn bound in the plan matches the current `|baseline| < π` checks (`lib.rs:238-239`), but a limit span that straddles ±π is where the measurement wraps; see nonblocking item.

**P1. The lid breaks the current contact rule.** Native brakes on any active contact with a non-frame body (`lib.rs:371-385`). Erlang reports the lowest-ID partner (`tree/src/quod_physics.erl:809-811`). Prolog maps any contact to blocked and closed only when clear (`tree/priv/ontologies/quod_physics.pl:725-728`). A lid that reaches target while resting on its chest rim therefore finishes as blocked(chest) unless the chest is the joint's fixed body. Required change: state that the body the moving part closes against must be the joint's fixed body in this slice (joint contacts disabled), and state the shared result precedence: within tolerance and clear is closed, any other contact is blocked(Other), otherwise no result. Also state the one-partner selection rule explicitly, since it is currently hidden.

**P1. Door and rest disagree on custody admission; the plan must pick the rest rule.** A new close unconditionally drops existing custody (`quod_physics.pl:662` via `physics_remove_door_request`), including unresolved custody whose finish may still be in flight. The rest path refuses a new request while custody is unresolved and allows replacement only after finished, certified rejection, or cancelled plus revision change (`quod_physics.pl:807-829`). The archived ruling is explicit that owners never destroy live obligations they will need again. The plan says "keep original custody" but does not say which admission rule the shared library uses. Required change: one `physics_*_replaceable` predicate for both hinge and rest, with the rest semantics; new close refused while custody is unresolved; cancel plus group move is the exit; old bytes stay resolvable and the old finish stays ineligible. Carry a test for never-submitted custody followed by cancel, refused re-close, group move, successful re-close.

**P1. Fixed-body sharing is unaddressed and currently fails closed for the whole world.** Native uniqueness is checked on moving IDs only (`lib.rs:225`), so one fixed body can host two joints. The plan's group move bumps the fixed body's revision; the other joint's `FixedRevision` goes stale; the Erlang decoder badmatches (`quod_physics.erl:733-735`) and the entire projection becomes `invalid_physics_projection`. Required change: either define group as fixed body plus all attached joints (move bumps and cancels all), or state one joint per fixed body in this slice and reject in both constructor and decoder.

**P2. Enumerate the door-isms to remove.** The plan says no zero target remains but does not list the rest: `tolerance >= baseline` refusal (`lib.rs:244`; a lid may start at target and closing an already-closed lid must brake on the first step), `Angle > 0` in `physics_valid_motor` (`quod_physics.pl:649`), shared leaf/frame revision (`lib.rs:233-234`, `quod_physics.erl:734`), box-only and zero-rotation requirements (`lib.rs:229-232`), brake on `|angle| <= tol` rather than `|angle − target|` (`lib.rs:367`), drive resetting limits to `±|baseline|` (`lib.rs:340-341`), and the symmetric angle bound in `physics_door_measurement` (`quod_physics.pl:720`).

**P2. Say what the moving body's authored pose row holds.** The constructor stores the frame position as the leaf pose (`quod_physics.pl:582`) and native overwrites it. The row pose is validated against the coordinate allowance at install, but the restored pose is not checked until the first step fails with `coordinate_allowance`. State the row's meaning (computed baseline placement, or placement anchor documented as such) and check the restored pose at install.

**Is one target-or-contact/hold policy enough?** Yes for door and lid, given the two P1 fixes above. Cancel maps to hold at the measured angle, restart restores then re-drives only when custody is none, and a gravity-loaded lid is held rigidly by the zero-width limit. Opening is the same policy with a different target. A motor stall without contact never samples; cancel is the only exit. State that limit in the spec.

## Acceptance obligations the plan omits

- **Joint-shape callers** that must keep refusing hinge members: `physics_unconstrained_body`, `physics_free_body`, `physics_move_body`, `physics_refresh_definition`, `physics_removable_body`, the Erlang rest checkpoint exclusion (`quod_physics.erl:774`), and native `restore_rest`/`push_body` (`lib.rs:149,199`).
- **Decoder invariants** at `quod_physics.erl:672-676`: every hinge has exactly one activity row and vice versa, hinge checkpoints need an activity row, a stale hinge checkpoint is a visible projection failure. Keep all three.
- **Generic command gating**: a position command is issued only while custody is none, finished or cancelled means hold (`quod_physics.erl:390-393`). State this as a rule, not as an incidental.
- **Positional world row**: the runtime destructures the row and rewrites element 13 (`tree/src/quod_runtime.erl:952,2667,2672`). Keep positions or update both sites.
- **Tests not in the carry list**: client view lifecycle with a body-driven mark and a close (`tree/test/quod_physics_tests.erl:2049-2155`), cross-ontology class recipe with grant and later class retraction (`:3425`), live-source obstacle as the contact partner (`:401`), controlled compound agent as blocker plus escape by motion query (`:3100`), refusal reasons with unchanged applied height (`:806`), generic observed clause cannot consume a request (`:3564`), failed-alternative outcome capture (`:3196`), sleeping does not erase reconciliation (`:3544`), and the Rust two-hinge test where one blocks, one closes, an obstacle edit wakes the braked leaf, and a checkpoint restores (`lib.rs:661-714`).

## Nonblocking suggestions

- Key observations by resource identity and put revisions in the row, not the key. A revisioned key orphans the retained observation entry and loses `outcome_height` on every edit.
- `activity/1` runs an Ed25519 verify per custodied activity on every projection (`quod_physics.erl:755`). Memoize by bytes or have Prolog supply the operation key.
- Bound `Upper − Lower` to at most π so the swing cannot cross the ±π seam.
- Have native return stop reason and contact in `hinge_samples` with the joint revision, so Erlang stops recomputing partners from the frame.
- The packet lacks the ontology loader. Confirm that consulting `quod_hinged.pl` into the same ontology merges `physics_activity/5` clauses without a new loader concept; if not, keep the library as a section of `quod_physics.pl`.
- Under new binaries an old-format scope decodes to `invalid_physics_projection`. That is the correct fail-closed behaviour and should be stated in the deployment contract as the expected symptom.
