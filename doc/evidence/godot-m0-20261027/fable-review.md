## Findings by severity

**1. Medium. The endpoint inner decoder now rejects binding values the sender accepts.** Correctness, not security. In [quod_dtx_endpoint.erl:257](/tmp/quod-godot-m0-handoff-31de17b5-20261027-03/review-tree/src/quod_dtx_endpoint.erl:257) the inner frame is parsed by the depth-bounded wrapped decoder, whose depth counts from the `{Inner, Hints}` root. The sender validates bindings at [quod_dtx_endpoint.erl:627](/tmp/quod-godot-m0-handoff-31de17b5-20261027-03/review-tree/src/quod_dtx_endpoint.erl:627) through the wire-term encoder, whose depth counts from the bindings list. The framing above a binding value is five levels deep on the receiver and two on the sender, so a value nested 60 to 62 compound levels passes `encode_response` and is refused by `decode_response` as `bad_etf`. Before this patch the inner used `binary_to_term`, which has no depth bound, so this asymmetry is new at this seam. Trigger: a committed outcome whose binding holds a deeply nested Prolog term. Effect: a local outcome read succeeds while the remote read fails closed, which is the same failure class R1 just fixed. Violated invariant: the one stated in the decoder's own module, producer and verifier must share one representation rule. Needed verification: a unit test that builds the deepest value accepted by `quod_wire_term:encode/1` under the bindings framing, confirms `encode_response` returns ok, and asserts `decode_response` returns the same term. On the reviewed tree that assertion fails. Fix direction, consultative: have the producer refuse what the verifier refuses by validating the built inner bytes with the same shared decoder at encode time. Do not raise the receiver's depth. The other `decode_wrapped` seams may carry the same class against `term_to_binary` producers. I did not verify them and they are outside this delta.

I compared the cached upstream Cowboy 2.12.0 and 2.13.0 hex packages, immutable artifacts outside the review tree. The actual difference is in `stream_next`. In 2.12 a connection made passive by exhausted flow is reactivated only when a pipelined next stream already exists. With no queued stream it stays passive, exactly the retained state. From 2.13 the reactivation runs unconditionally before that branch. The quod precondition is [quod_client_http.erl:165](/tmp/quod-godot-m0-handoff-31de17b5-20261027-03/review-tree/src/quod_client_http.erl:165). A body larger than the 65535-byte initial stream flow arrives across several TLS records. If the final record is parsed before the handler's read reaches the connection, flow resets to infinity while active stays false, the later flow command becomes a no-op, and the stream ends with no queued successor. The connection then waits passively until the request timeout and the client's next keep-alive request sees "other side closed". This race explains the intermittency across campaigns. The dependency upgrade is the correct fix and the qualification stands. Needed action: correct the three causal statements. No code change.
