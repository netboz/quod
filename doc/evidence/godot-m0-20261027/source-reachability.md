# Actual loading and source reachability

The source census covers all **50** baseline Prolog files, with SHA-256, explicit filename callers, vocabulary pins and conservative predicate-name references. The final index includes runtime, Prolog, tests, scripts, native/browser/UI source and deployment manifests. A same-name predicate match is not proof of a real call; lack of a textual match is not proof of dead code. The [disposition map](retirement-map.md) retains behavioral obligations and later move prerequisites for every source.

There is no general Prolog filename import graph that automatically composes all packaged sources. Existing owners load/freeze sources through these distinct paths:

1. [Committed projection](../../../src/quod_committed_projection.erl:613) reads `common_predicates.pl`, `construction.pl`, `material_policy.pl` in that order from the packaged directory for each projection bootstrap/recovery. The [runtime manifest](runtime-manifest.json) pins their bytes separately from ontology genesis. Their availability is not inferred from catalogue queries.
2. [Application configuration](../../../src/quod_app.erl:455) resolves configured genesis paths under `priv`. [Default config](../../../config/quod.conf) and [Nomad bootstrap](../../../deploy/quod.nomad:376) select root genesis. [Root module selection](../../../src/quod_app.erl:468) freezes `[quod_directory_predicates,quod_ontology_predicates]` into root's founding manifest. A normal restart restores that existing genesis; it does not found every catalogue namespace again.
3. [Ordinary founding preparation](../../../src/quod_ontology.erl:406) reads authorized `source_file` inputs in order and normalizes terms/modules before the existing atomic creation effect. Sources become committed genesis terms; subsequent recovery is from that history, not rereading files. A packaged file may be deliberately supplied by an authorized authored founding call even if no startup code names it.
4. [Node class recipe](../../../priv/ontologies/quod_node.pl:79) accepts only its committed exact class/template/key inputs, not an applicant-selected filename/module list. It uses `source(Source)` containing frozen `node_execution.pl` bytes and `[quod_ontology_predicates]`. [Lifecycle fixture](../../../test/quod_lifecycle_single_path_tests.erl:1226) exercises the real template, exact class policy, enrollment, restart and hosting lifecycle.
5. [Signup recipe](../../../priv/ontologies/quod_signup.pl:108) constructs `source_file` options from its reviewed component facts and configured source directory. In declared order these are **human_user_instance, agent_instance, personal_agent, space, gui_hud, gui_instance, gui_operation, controller_preferences**. It adds exact lobby/GUI pins, key, pending provision and receipt origin, using `[quod_agent_predicates]`. These are actual source composition, not comments describing a hypothetical import.
6. [Current lobby recipe](../../../priv/ontologies/quod_lobby.pl:36) consumes committed `lobby_source_file` facts and exact vocabulary pins. Its physical floor/sky/pilot composition is a policy input; it is not required by ordinary `space`. The [real lifecycle fixture](../../../test/quod_lifecycle_single_path_tests.erl:1339) supplies **lobby_instance, space, agent_instance, quod_physics, space_view, voxel_world, voxel_world_view, gui_instance, gui_operation, space_gui, gui_question, voxel_world_gui, lobby_worlds**. A deployed genesis may have a different committed composition; current packaged bytes are not asserted equal to that live history merely because a name/anchor exists.
7. [Optional deployment benchmark](../../../deploy/quod.nomad:388) directly selects `cross_benchmark_source.pl`/`cross_benchmark_target.pl` when enabled. They are not dead and removing them from a production package requires updating that configuration/tooling. The proposed test-only destination preserves their load/ask obligations.
8. Shared catalogue vocabularies and optional compositions are founded through ordinary governed calls and pinned exact identities, not an Erlang per-namespace domain loader. The old [catalogue](catalogue.json) records 18 rows at height 69 plus configured root, with exact anchors. New consolidation pins cannot reuse those old anchors. Tests/authored source remain legitimate callers of optional physics, recovery, FIPA, naming, licence, material, tooling, terrain, examples and question code.

[Per-source loading tags](source-reachability.json) records these concrete paths for every source, alongside its named caller and test obligations. All 50 are packaged in the current baseline and are therefore potentially admissible to governed authored source-file selection. The seven fixture destinations in the proposed retirement map are delivery choices after checking configured/authored callers, not a claim of current unreachability.

M1a replaces source composition and exact catalogue registrations through the ordered recipe in the [foundation contract](../../godot-foundation-contract.md). It must preserve complete source manifests and receipt privacy; it must not temporarily found the removed identities or add a second founding framework. Actual fresh-foundation and signup integration remains M1a acceptance. M5 removes old active source paths only within that verified replacement scope and excludes archives from compilation, application module manifests, package resources, bootstrap and runtime selection.
