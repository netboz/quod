# Native GUI alignment273

The existing tracker owns scheduling. This matrix compares the current native
owners with the GUI plans; it does not define another authority or framework.

| Requirement | Existing owner and observation | Disposition |
| --- | --- | --- |
| World-stable floating working panel; Move, Recenter, Hide | Main → SpatialGui → OpenXRInput; one native control surface, explicit placement | Implemented; floating panels are permitted by the specification |
| Compact attention; human-selected primary form; arrival never opens every form | QuestionHub currently appends every discovered QuestionPanel and Projection shows its form | Real signed/native baseline pending; correction in this owner |
| Same form, control, draft, exact target and signed outcome | QuestionPanel/FormPanel/SignedSession; local dismissal differs from gui_cancel | Preserve and qualify affected selection/lifetime paths |
| Authored solid material factors and readable faces | Core Scene decodes then discards metallic/roughness/emission; ScenePanel renders every primitive unshaded | Real oblique raster baseline pending; shared adapter correction |
| Ontology-authored appearance and local accessibility | FormPanel/SpatialGui; foreground opacity and Larger text retained | Reuse accepted appearance contract; qualify changed composition |
| Adjacent opaque keyboard and guarded native rays | SpatialKeyboard/SpatialGui/OpenXRInput | Reuse owner; qualify selected working form, no hardware action |
| Generic form occurrence → authored object surface binding | No current native binding schema/consumer | Open contract gap; no schema invented in273 |
| Measured Vive apparent size, spacing, distance, texture density and comfort | Fixed workspace dimensions and adjustable native scale/placement | Human/device qualification open; software clipping is insufficient |

The blue cube is a space's authored exterior, not its interior. Material changes
must apply to ordinary solid primitives, not a colour, class or Library name.
The surface's fourth factor is emission, never opacity. No domain action follows
from opening, shading, selecting, hiding or reflowing a presentation.
