Review complete. Findings in severity order, then the verdict.

**1. High: door actions now admit a rotated pose the native hinge cannot honour.** The old validator at `before/priv/ontologies/quod_physics.pl:355` only unified `vector(X,Y,Z)`, so `physics_add_door` and `physics_move_door` could not store a rotated frame. The shared schema accepts `pose(_, rotation(_,_,_))` at `priv/ontologies/quod_physics.pl:367`, and both door actions pass the caller's `Position` straight through at lines 343-344 and 518-519, then assert it as the frame and leaf pose. The adapter installs the frame with that rotation at `native/quod_physics/src/lib.rs:112,131`, but `install_hinges` places the leaf in world axes and builds the revolute joint on local `Y` at lines 281-293, and `hinge_angle` measures relative to the frame at 318-321. Nothing rejects a non-identity frame orientation, so a signed door edit with a rotated pose installs a hinge whose axis and measured angle disagree with the authored baseline and checkpoint. Closed/blocked interpretation then rests on a misconfigured joint. The patch keeps the box restriction explicit but silently relaxed the pose restriction.
Fix: add `Position = vector(_,_,_)` beside the box guards at lines 341 and 517, extend the doc sentence at `doc/physics-native.md:66`, and add a rejection case through `physics_add_door` with a `pose(...)` position and one with a non-box door class. The adapter should also refuse a non-identity frame rotation in `install_hinges` as part of its stated supported-joint check.

**2. Medium: two schema fields have no encoding envelope.** Rotation components at `quod_physics.pl:368` and density at line 362 are only checked `integer`. The adapter divides and floats them at `src/quod_physics.erl:657,663`; a bignum raises `badarith`, which `projection/2` at line 623 turns into `invalid_physics_projection` for every world in the ontology. The Id bound at line 361 shows the intended pattern. The door-class path makes this reachable: density comes from an authored, possibly remote, class. Fix: bound rotation per component (±3142 mrad covers every orientation and matches the query envelope) and give density an explicit representable bound.

**3. Low: refusals carry no reason.** A coordinate-allowance overflow and a malformed shape both surface as bare `failed`. Sibling actions use `fail_with_reason` (lines 549-556). Wrap the validator call so the exceeded resource or malformed field is named.

**4. Low: residual duplication.** `physics_query_vector(Position,Coordinate)` at line 495 now overlaps the shared validator; keep it only as the structural guard `Position = vector(_,_,_)`. The `Index < 4294967296` test at line 395 repeats the Erlang decode guard at `quod_physics.erl:683` and is subsumed by `Index < Count`.

**5. Low: coverage is narrower than described.** All six supported-shape cases force the body to `fixed` (`test/quod_physics_tests.erl:35`), so no dynamic or controlled non-box body passes through the move action and the native mass check. The rejection list covers no Id, density, pose-position or part-pose range cases and nothing for the hinge restriction. "Rolls back" is inaccurate: validation runs before any retract, so the test proves refusal before mutation, not rollback. The world is never enabled there, which is fine but should be stated.

**Shared validator assessment.** One predicate, three callers, old five-arity clause gone, no Erlang duplicate added. The Erlang guards at `quod_physics.erl:652-690` are pre-existing decode guards, not a second domain engine. The box guard is an explicit domain restriction, not a compatibility path. Growth of 37 lines is the schema itself. Schema versus native split is correct: hull volume, triangle area, compound bounds and mass stay in `geometry.rs`.

**Verdict.** The geometry prerequisite is sound in shape but not acceptable as frozen because of finding 1, which is a regression introduced by this patch. With the two one-line pose guards, the rotation and density envelopes, and the two missing rejection tests, I would accept it as the shared schema for the later admission work. This says nothing about the full feature.
