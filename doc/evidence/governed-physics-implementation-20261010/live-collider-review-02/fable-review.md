**Verdict:** the corrections are real and the atomic composition, fences and per-world isolation hold up in code. Two items still need a fix or a decision before I would call the slice integration-ready; neither is a consistency or authorization defect.

## Required fixes or decisions

1. **A slow foreign log at selection time pauses a world with no wake.** The final currentness check is capped at one second, not the original deadline (`tree/src/quod_foreign_log.erl:973`). A timeout there is reported as `source_not_ready` (`tree/src/quod_runtime.erl:246-248`), the world lands in the unavailable list, and the selection still completes with reply `ok` (`:262-275`). Nothing requeues it: `resource_finished` records no failure (`:1114-1126`), and the only wakes are a source fence change or a local basis change (`:1847-1877`). The same cap applies to the fence re-check in `source_basis_current` (`:2650`), which first answers `selection_superseded`, requeues, and then hits the path above on the second pass. So a transient stall of the foreign log mailbox leaves that world paused until an unrelated commit happens. The fix is to distinguish the owner-call timeout from `building`/`not_found`, and either wait under the worker's real deadline in the worker or keep the world flagged for reselection. Do not weaken the fence itself. Related: both calls run inside the runtime's own `handle_call`, so the state owner blocks for up to one second per live source per check.

2. **The signed view's source read moves the "irrelevant source change" problem to the client.** Review 01 item 1 is fixed at the owner: the pause keeps viewer and inputs (`tree/src/quod_physics.erl:146-155`) and the test proves it (`tree/test/quod_physics_tests.erl:28-35`). But `physics_client_view` now performs a cross-ontology read per live body (`tree/priv/ontologies/quod_physics.pl:439-440, 464-469, 20-26`). That adds every live source scope to the view's dependency set, and the simulation socket refreshes on any higher certified height at a foreign dependency (`tree/src/quod_client_simulation.erl:385`). Refresh releases the watch, which marks the controller's input `disconnected` (`tree/src/quod_physics.erl:608-618`). So through the production client path an unrelated source commit still retires the view and voluntary input. The continuity test never opens the client view; it watches the owner directly (`tree/test/quod_physics_tests.erl:14`, `:1056`). Two further consequences: every viewer needs source entry grants for three goals, which the fixture hides with a blanket `can_invoke` (`:421`), and a source denial reports `unavailable` rather than `denied` (`quod_physics.pl:443`). The runtime already fences source authorization and geometry at install, and every geometry change reaches the destination through a structure bump, so the view read duplicates an existing guarantee. My recommendation is to drop it and keep source dependencies in the resource basis only. If it stays, document the per-viewer ACL requirement and the client refresh cost as a limitation.
