**Verdict:** the stage is sound enough to keep integrating. The transitions, exact fences and per-world isolation are implemented as the plan describes, and the lifecycle test exercises the real atomic lane. Four items need a decision or fix before this slice can be called complete, and release acceptance is still blocked by missing evidence.

## Required fixes or decisions

1. **Every unrelated source commit drops the viewer and suspends hot controls.** Each materializer advance sends `{building, H}` to projection followers (`quod_foreign_projection.erl:171`, `quod_foreign_log.erl:3896-3904`). The runtime treats that fence change as invalidation (`quod_runtime.erl:1802-1808`), and the owner's `physics_invalidated` handler clears the viewer, sends `physics_refresh`, and suspends every input (`quod_physics.erl:146-151`). Geometry is retained and no native work happens, but a player loses control whenever the object's source ontology commits anything, even a chat line. Local changes only invalidate when the basis is affected (`quod_runtime.erl:931-937`); source changes should use the same rule, or the pause must stop stepping without retiring viewer and inputs. The plan's "irrelevant-source change" measurement would have caught this and is still pending.

2. **`physics_body/7` now follows the source in every consumer.** The live branch of `physics_resolve_definition` does an `Ns::` read (`quod_physics.pl:24-30`), and `physics_body/7` is used by door measurement in reaction matching (`:676,678,685`), hot-control staging (`:322`), signed views (`:428`), and body reads (`:234`). Only `physics_move_body` (`:702`) needs the resolved shape. A door blocked by a live obstacle, or a live controlled body, would make reaction matching and every input proof perform a cross-ontology follow; no test covers either. Either verify `::` is legal and acceptable in those contexts or derive the shape-free consumers from `physics_body_definition/6` directly.

3. **Authority replacement has no path.** Delegation binds the authority instance (`quod_physics.pl:61`) and resolution requires that exact grant (`quod_runtime.erl:2640-2643`). Changing `physics_space(W, enabled, I)` to a new instance pauses every live body permanently: `physics_delegate_definition` refuses while a grant exists (`:60`) and `physics_release_definition` needs a staged withdrawal (`:66`). Host moves are unaffected. The plan lists authority replacement as a required scenario, so either add a re-delegation transition or record it as an explicit limitation.

4. **Refresh is gated on the full world-edit grant.** `physics_refresh_definition` requires `can_edit_physics(W, P)` (`quod_physics.pl:138`), the same grant that adds doors and moves any body. An object owner cannot reshape their own placed object without that grant. The test confirms the behaviour (`quod_physics_tests.erl:18-24`). This is a policy choice, but it should be deliberate; a narrower destination hook would match how admission is gated.

## Optional improvements

- One invalid local row still stops every world: `quod_physics:projection/2` is all-or-nothing (`quod_physics.erl:629-635`) and the error path calls `stop_physics` (`quod_runtime.erl:272`). The plan asked for per-world failure where identifiable.
- The runtime owner makes a synchronous call into the foreign log per live body during `resource_selected` and `project_physics` (`quod_runtime.erl:2602`, `quod_foreign_log.erl:968-974`). A busy foreign log stalls the namespace runtime. The follow-row fence already covers materializer replacement.
- `resource_selected` checks only the new basis for external callers while `project_physics` checks the merged basis (`quod_runtime.erl:307-318` vs `:254`). After any source fence change, an external `reconcile_resource(physics_worlds)` call is superseded once. The test helper uses that external path (`quod_physics_tests.erl:1379-1381`).
- Withdrawal requires exactly one live body (`quod_physics.pl:88-90`), so an entity admitted under a no-effect rule, or with its body removed by raw edit, can never leave. Admission also refuses while physics is disabled (`:72`).
- `install/2` compares bodies, hinges and restores together (`quod_physics.erl:291-305`), so every door or rest checkpoint commit re-sends all bodies to the native layer. Whether that is a native no-op cannot be verified from this tree.
- The admission check `subscribes(Ns, Anchor)` (`quod_physics.pl:73`) is satisfied by a derived rule, but the runtime only follows stored declarations; such an admission would pause forever.

## Acceptance still missing

Per plan section 5 and not in the frozen tree: edit versus withdrawal race, denied export, stale source and body fences, source loss mid-run, authority replacement with live bodies, reconnect and recovery without replay, and the two cost measurements. The lifecycle test uses a second local ontology through the foreign log cache, which is the production seam but not a remote source. Clean sequential gates, the fresh personal-space baseline, authorized deployment and desktop collision acceptance remain open.

What I verified as correct: exact assignment, delegation and definition-revision binding at both owners; staged callbacks that cannot complete half a transition; rollback of a denied receiver consequence; source reads pinned to the worker under the original deadline and released on exit; duplicate notices as no-ops; source loss suspending only the affected world; busy-owner selection coalescing; and unchanged geometry skipping native installation.
