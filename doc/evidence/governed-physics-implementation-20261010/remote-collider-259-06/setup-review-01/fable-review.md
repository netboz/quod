## Lifecycle assessment

- **Root admission is correct and necessary.** The second founding failed because custody requires the executor to be a ready root participant: `quod_effect_journal.erl:1621-1627` demands a dtx binding, which `quod_simplex.erl:4605-4617` only yields with `sync = ready` and `is_participant`. No grant can substitute. A hosting transfer would not help either: `quod_node.pl:121-122` gates `join_ontology` on `peer_admitted` too. So admit, create, remove is the single existing path, not a shortcut.
- **Admit/remove go through existing owners.** `admit/3` stages under `can_join` (`quod_committee_predicates.erl:76-89`), every validator re-proves it, and `remove/1` retracts by pattern with a last-member floor (`:95-111`). With node0 the sole judge there is no `peer_ready` verdict split.
- **Readiness hazard after admission.** Admission re-seats node1 as `sync = unconfirmed` (`quod_simplex.erl:14385-14395`). An applied-height and committee check is not enough: creation will return `not_in_charge` again until node1 corroborates. The pre-create check must be the same predicate custody uses, `quod_simplex:dtx_ready_binding/1` returning node1's own key, taken after a `{runtime,root}` wake, not polled.
- **One-shot risk is real but bounded.** 1→2 and 2→1 both need both votes (`quod_committee_predicates.erl:30-34`). If node1 dies in the window, root freezes until Nomad restarts it. State this in the campaign record.
- **Effect terminality before removal.** A committed `{ok,...}` from `quod_prolog:execute` already implies the effect journal awaited the lifecycle effect (`quod_prolog.erl:5123-5130`), so removal after a definite `ready` state is safe.

## Blocker not addressed by the plan: A is unreachable from node0

A root-only `create_ontology` starts A on node1 but publishes no route. Ordinary descriptors require the author's committed `hosts_ontology/4` fact with discoverable visibility (`doc/lifecycle-and-routing.md:35-37`), and the manager publishes a non-system ontology only from committed node hosting facts (`quod_namespace_manager.erl:1575-1581`). The designed shape is the composed create+host transaction (`:234-237`, as enrollment does in `quod_node.pl:48-56`). Without it, node0's `subscribes(A)` foreign follow waits on a route forever and every `observed_submit` dies with `source_advance_missing` after the source op has committed. Required: node1 authors creation and its own discoverable hosting fact in one atomic transaction through its node identity ontology, then the runner confirms on node0 that the directory resolves A before activation. Whether node1's identity template exposes a general `host_ontology` action is outside the frozen tree. If it does not, that is a policy gap for Yan, not something to patch with an injected route.
