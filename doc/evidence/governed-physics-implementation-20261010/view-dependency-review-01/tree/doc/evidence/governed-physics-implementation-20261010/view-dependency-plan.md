# Signed view dependency retention

This is the next local implementation stage of QUD.27. It extends existing proof and simulation-view owners. It does not introduce another physics authority or a synchronization protocol. The earlier capability-epoch and separate-domain alternatives are superseded by common system-predicate registration. No backward compatibility is required.

## Concrete gap and existing owners

The origin worker already pins every successfully opened scope in `quod_proof_context`. Those scopes survive failed alternatives, negation and rollback. Origin identity and applied height are known at `run_pinned_origin`. Co-hosted scope workers retain their opening height in `quod_prolog`'s existing worker record. Remote scope-open events carry an authenticated `BaseHeight`; `quod_ask:await_remote_scope_open` currently discards it, and the router does not retain it for an exact repeated open. Ordinary read finalization closes scopes and `finish_proof` returns only the origin height.

The signed simulation endpoint currently subscribes only to acting-agent and physics namespaces. It therefore cannot validate an additional visible-world, permission or geometry scope. A disabled selection cannot wake from its actual policy dependencies. Authored dependency lists would not establish what a proof really read.

## Proposed extension

1. Retain each opening height alongside the existing scope registration, including origin. Change the internal opener success to `{ok, Owner, Handle, Height}`; the public `get_or_open_scope` result and opaque scope handles need not change. Co-hosted opening returns its existing worker height, including exact repeats. The router retains the received base height in its existing scope row and returns it on exact repeats. No new scope wire operation is needed. An unavailable or refused opening supplies no invented height.
2. Expose one immutable snapshot list from `quod_proof_context`: exact namespace, genesis anchor and applied height for every opened scope. Collect before cleanup. Include scopes observed by failed alternatives and denied target invocations; do not roll them back with staged writes. This is conservative per-ontology view invalidation, not a replacement for OCC tokens or row-level precision. The acting-agent origin is always included and covers its key/authentication reads.
3. Carry that evidence through the existing signed read completion and canonical client-result owner, for successful and failed read outcomes. Use one signed-read envelope containing snapshot dependencies plus the existing normalized read outcome. The trusted in-VM proof API, cursor, durable writes and transient controls retain their own semantics and execute through the same proof owner; do not create a separate physics proof engine. Update existing signed-read consumers/tests to the new canonical result, with no old/new wire decoder branch. HTTP may render dependencies as additional exact-reference fields while the simulation endpoint consumes the same normalized envelope.
4. The simulation socket verifies the signed request as today, then subscribes to every resulting dependency BEFORE taking current snapshots. For local scopes pin the current engine incarnation and exact genesis/height; for foreign scopes reuse caller-owned `quod_foreign_log` progress follows and their authenticated notices. A changed/unknown/recovering dependency prevents attachment and triggers a fresh ordinary signed read only when its existing owner reports progress. Do not poll. Duplicate/stale notices from retired follows/engines are ignored. Deadlines and request expiry remain the originals.
5. Retain view dependencies even when Prolog selects nonphysical, disabled, denied or recovering. View selection runs from the anchored visible-world scope, with the signed acting agent unchanged, rather than assuming physics selection is in the acting-agent ontology. Prolog selects the existing world and typed status. Native installation remains a separate check at the runtime/physics owner. A formerly controlled view that loses authority stays paused until a fresh authorized selection; unavailability cannot switch it to observer travel.
6. On dependency advance, release old pose/control authorization before requesting a fresh view. Reconnect and owner replacement create fresh view requests but never resubmit an uncertain movement/domain operation. Admission/withdrawal and durable occupancy consequences remain in their existing transaction and authenticated observation owners.

## Verification

Exercise origin, co-hosted and real remote scope openings, including exact repeated opens, wrong anchors, failed branches, denial, and rollback. Confirm returned heights are the actual pinned heights when an owner advances during a read. Cover subscribe-before-snapshot races, owner restart, foreign follow replacement, duplicate notices and absolute expiry. In the signed socket, enable a previously disabled world through a committed dependency change and revoke a grant in a third ontology. Only that view should refresh; an unrelated ontology must not. Repeat unchanged checks with the existing no-history-replay/no-rebuild/no-write trace. Full live collider installation and signed current-lobby collision acceptance remain separate outstanding stages of this same ticket.

## Review boundary

Claude/Fable should check the precise result-envelope boundary and negative/unavailable behavior against the source before implementation. In particular, identify any authorization reads outside retained scopes, any loss of pinned height on co-hosted/remote reuse, or any local/foreign readiness condition that would require a fabricated snapshot. This extends retained read metadata; it grants no new Prolog rights and changes no founding manifest, ledger history, commit validation or transaction custody.
