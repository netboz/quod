# Atomic opening independent review

Public gui_open now uses the original authenticated operation, ordinary scoped
policy proofs, a declared GUI action and the existing effect journal. The
responsible ontology creates its awaiting row and the human HUD reference in
one transaction. Source schema, exact identities, authored receiver/capacity
and responder policy are checked through their current owners. Native
preparation checks the actual installed reaction and obtains the authenticated
client's acknowledgement before staging the real presentation effect.

The action's opaque request handle and proof-local staged desired state prevent
an authored fact from fabricating acceptance. Prepared private bytes retain the
original authenticated request. Actual journal release activates the same client
receipt; neither receipt nor activation decides material outcomes. A disconnected
receiver after acceptance does not invalidate an already committed question.

Self-reviewed, not Claude-reviewed. Final gate07: six question tests, zero
failures, true exit0, 24.854s. Gate04 also included components/examples: nine
tests, zero failures, true exit0, 68.649s. The live fixture covers missing human
selection, actual responder loss while preserving an accepted question, outer
proof rollback after native acceptance and both staged rows, explicit client
refusal, two concurrent prepared openings with a certified conflict for the
loser, stale receiver selection and withdrawn handler. The applied journal row
is joined through its real completion API, not inferred from a sent frame.

Failures retained: gate02 called a nonexistent fixture helper and leaked the
test journal before cleanup, producing subsequent already-started failures.
Gate05/06 demanded a short exact refusal within the whole proof's bounded
diagnostic stack. Gate06 exposed truncation of that stack. Gate07 checks the
actual native-handler query's explicit unavailable reason, then the public
opening's definite logical failure and unchanged shared question/HUD state.
No production semantics or diagnostic budget changed to satisfy the fixture.

This is a local live-opening integration, not a claim of remote end-to-end
opening, full live application examples, automatic observation-only recovery
or headset acceptance. Existing transport tests cover selected observer scopes
separately. Those remaining obligations prevent ticket completion.
