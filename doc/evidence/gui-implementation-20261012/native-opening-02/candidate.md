# Native preparation through existing scope and effect owners

Candidate for internal source review; this is not an implemented API or a claim
that gui_open works. Preserve the earlier rejected candidates and their evidence.
No new GUI RPC service, journal, question queue or domain executor is proposed.

## Required native capability

A receiving node must serve the anchored GUI vocabulary as an ordinary read-only
ontology scope (observer membership is sufficient). The responsible actor's node
already serves its actor ontology because its runtime owns the installed actor.
A browser gateway may currently follow the human's ontology only through a foreign
projection: do not assume a local human Prolog owner. Use the GUI capability scope
for native presentation, not the human ontology. Missing capability/route is an
infrastructure condition, never a successful preparation or authoritative absence.
Do not silently join or found any namespace to repair an ordinary request.

Check this capability requirement against actual startup/founding and client node
configuration before implementation. It is an explicit integration condition, not
a claim that all existing client nodes already meet it.

## One original request and one existing action

The source's shared gui_open compiles the form and selects human/responder under
ordinary policy. It derives the question identity from current_request_operation.
The human's signed gui_selected_receiver row selects exact node/connection. The
responder's normal hosted policy selects node/epoch/key and authored allowances.
These remain ordinary main-proof reads and participate in sealing.

The GUI vocabulary's declared action is effect-only; source, responder and human
material scopes retain normal OCC and authority. The shared action helper now
accepts a private transition, so no separate action dispatcher is necessary.
Its opaque handle and candidate savepoint remain mandatory.

A private native preparer needs a selected-node read scope. Reuse scope bindings,
identity admission, invocation commands, transport router and cleanup. It must
have a separate read-only proof context so it cannot change the mode or move an
existing material scope. It inherits the original verified signed bytes, proof
identity, principal, certificate and absolute remaining deadline; it does not
sign or submit another execute request. A temporary worker is tied to the caller,
not a new state owner. Normal nested read calls still use ordinary scoped ACLs.
Results are consumed into the actual private presentation preparation, never
returned as an application-visible liveness fact or made sealable in a writer.

Do not implement this by exporting a generic discarded live-query bridge. Only
the private native action invokes it, and a successful result must correspond to
an actual provisional client resource retained until activation or expiry.

## Installed actor feasibility

The selected actor scope verifies normal source/human/actor policy and reads the
actual shared reaction clause from its current snapshot. The existing runtime
compares the exact expected binding and clause against its installed actor and
reaction catalogue. It must refuse a missing/retiring actor, wrong epoch/key,
missing handler or authored capacity. Owner/readiness failure remains an error.
No fabricated event is dispatched, and no per-question actor registry is created.
The private acceptance identifies the actual runtime/actor incarnation; epoch/key
alone do not identify a process restarted under unchanged policy.

Before coding, pin the clause fingerprint to the existing canonical normalization
and the precise runtime catalogue frontier. Queue-budget policy must remain in
Prolog if queue capacity participates; do not copy or increase Erlang constants.

## Connection preparation and release

On the chosen GUI capability scope, the native bridge asks the exact existing
signed HUD socket to accept the descriptor. A registry address alone is not
acceptance: the socket checks its exact human, active signed authorization and
expiry, then obtains client support/capacity acknowledgement. The client allocates
its hidden local presentation using the common descriptor/control adapter. A
malformed/unsupported form or definite refusal fails inside the original action.
A transport timeout is an infrastructure error before any material dispatch.

The receipt binds original request, anchored question, descriptor digest, node,
connection token, native provisional token and original expiry. Hidden resources
expire at that bound and are discarded on connection death. They are neither
question status nor another domain queue. Rollback must not expose the hidden
resource; cleanup may cancel it, while expiry bounds lost cancellation.

HUD projection invalidation can occur because the same opening commits its HUD
link. It must not erase an already accepted provisional resource or confuse its
connection with a replacement tab. While such a resource exists, the same socket
address can remain routable for its exact receipt even during a signed-view
refresh; new preparation still requires current authorization. No-preparation
sockets retain the already-tested unregister-on-invalidation behavior.

Extend the closed effect catalogue/codec through quod_effect and the existing
journal. Its ordered release invokes the exact receipt through the same native
scope transport, before original expiry, with the retained original authentication.
This is a native idempotent activation, not re-execution of the signed application
goal. Expired/disconnected preparation is terminally discharged. An uncertain
activation may be observed or discharged at expiry; it cannot block indefinitely
waiting for reconnection. The exact receipt is the idempotency boundary.

Activation makes the accepted presentation available through the existing signed
HUD/question controller. It does not insert a local authoritative question or
replace the shared HUD list. Rendering/submission still use the authorized current
question projection; committed HUD discovery remains available after disconnect.
Do not turn the effect into a no-op journal carrier or replace its release with
an unimplemented foreign feed.

## Material transition and custody

Responder and human entries must verify the exact staged desired state in the
same re-entrant GUI effect scope, as well as their ordinary source/caller policy.
They cannot trust a caller-asserted opening marker. Their question and HUD rows
commit with the prepared effect in one transaction; capacity and unique question
identity are normal committed-state checks. No per-opening executable clauses.

Existing source reservation retains the compact group, including exact original
request bytes/signature, before private effects are bound. The real-node source
crash test is being extended to check that exact binding and existing agent-work
custody visibility. Before that admission barrier only reversible proof/private
preparation exists; no material operation has dispatched. After the barrier the
existing Vote/Resolve/Complete owner has custody. This may remove the previously
assumed need for a separate pre-proof raw-request store; finish the crash evidence
and distinguish caller observation from durable source ownership before closing it.

## Checked startup seam

Source inspection found the existing owner already supplies the GUI scope: quod_namespace_manager follows the root system_ontology/2 catalogue through quod_system_ontology, materializes exact anchored joins, and merges them into its ordinary desired content. A catalogued quod:gui is therefore joined by that owner, including observer service. No request-time join or GUI-specific bootstrap is needed. Missing/catching-up capability remains unavailable; native bridge implementation must be included in the GUI ontology's governed genesis module list under the existing coordinated release/founding rules. No deployment or genesis rewrite is authorized here.

## Executable receiver contract to implement

Use the same authenticated /api/views HUD socket. Internal local owner messages use bounded gen_server call/reply envelopes delivered through websocket_info; no listener/RPC service is added. A private prepare receives exact human bytes, socket token, original request digest, anchored question reference, portable question_form descriptor, authored capacity and original expiry. The server checks current signed installation/expiry and exact human/connection; a stale route is authoritative absence only on that chosen node. It asks the browser to prepare by a cryptographic correlation token. A map in that socket holds only provisional native resources, never shared question status or answers. Duplicate exact preparation observes its same resource; conflicting or still-pending preparation does not allocate again. Client acknowledgement is necessary before returning the receipt. Unsupported descriptor/refusal fails the action. Timer and socket loss dispose provisional resources; failed-proof resources remain hidden and expire under the original bound.

Client native messages reuse connectSignedView dispatch and the shared descriptor decoder. The UI allocates the existing questionController with deferred signed-view start; no authoritative form/status is seeded from a prepare message. Activation starts its ordinary signed question view. The HUD and selected desktop/spatial component must borrow that same controller, not create another draft owner. A local presentation map may retain actual controller handles keyed by question reference; it must not act as a domain pending queue. Temporary HUD refresh must preserve them. Exact authoritative HUD discovery hands a provisional resource to the ordinary view lifetime; retirement or identity closure disposes it. A resource never discovered before its original expiry is released. Neither preparation nor activation inserts a local pending-question row or bypasses signed projection authority.

Activation is a real idempotent native owner call on the exact receipt and socket. Its acknowledgement starts the prepared controller; it is not a no-op effect. An already active receipt replies active, a missing/expired receiver discharges that native opportunity. If an activation reply is lost, do not repeatedly activate on a readiness timer. The existing effect worker may await the original receipt expiry once and then discharge that opportunity; this is bounded protocol expiry, not readiness polling. A worker crash can observe/reconcile the same idempotent receipt through the existing journal. Do not extend its original bound or reinterpret that native expiry as a negative material-operation outcome. The committed question remains available through ordinary HUD discovery even if its original presentation opportunity expires.

The effect catalogue/codec must still be extended and tested before gui_open is exposed. Actor feasibility is now available via installed_agent_reaction in a selected native scope. Shared GUI signing now permits only the exact retained ground completion, eliminating the need for broad authored signing grants. Main-proof capacity and source/human/responder policy remain ordinary ontology reads and atomic writes; native results are consumed only into genuine private preparation.
