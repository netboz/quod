## Verdict and prioritized defects

**Verdict: not ready to implement as written, but section 5 is solvable with existing lanes.** The plan's reading of the owners is accurate. I confirmed each claim in its "contract requiring resolution" paragraph against the frozen tree: an event-only diff is a nonempty diff and is vetoed by any live bridge, `release_transient/2` returns only ok, refusal or uncertainty, and the custodied store is itself a material transition. What the plan lacks is the trace. I worked it through below, and it needs one semantic change to an existing owner plus adapter work, no new executor, queue or protocol. Three other defects must be fixed in the plan before coding because they change where state lives and what event-only forms may promise.

Evidence lines refer to the frozen tree under `tree/`. No build, test, browser or headset run was performed. I did not invoke the stop notifier because this packet forbids execution.

- **P1-1. Section 5 has no executable admission contract.** `tree/doc/gui-implementation-plan.md:228-246` names the gap correctly. The control lane already finalizes the selected read-only proof and then releases exactly one transient to a local owner, mapping refusal to reasoned failure and a lost reply to error at `tree/src/quod_prolog.erl:4424-4437`. The transient context requires a signed, read-only, ordinary-intent control proof at `tree/src/quod_erlog_db_local_prove.erl:240-266`. A hosted agent cannot issue a control request today: `tree/src/quod_agent.erl:125-128` has no clause for that mode and would crash, and agent work only emits execute requests at `tree/src/quod_runtime.erl:2239-2252`. That is the one concrete missing capability. The trace in the next section uses it.
- **P1-2. A recoverable question's row must live in the responder's ontology, not "the originating ontology".** Agent work is selected by a resource worker that runs the goal without a proof context and with no governed I/O, `tree/src/quod_runtime.erl:2788-2799` and `2869-2878`. A foreign `::` read cannot run there, so `agent_work_goal/5` can only select rows in the responder's own ontology, exactly as `tree/priv/ontologies/fipa_request.pl:71-78` does. Section 6 at `tree/doc/gui-implementation-plan.md:263-266` and example B's "host the responsible agent in another authorized ontology" at `:550-551` contradict this for recoverable forms. Event-only forms with a foreign responder are fine through `from/3` plus `subscribes/2`.
- **P1-3. Event-only mode cannot meet the guarded response contract as stated.** The reaction sees the event term and `me/1` only. Nothing in the matching context exposes who committed the event, and `trigger_event/1` is callable from any admitted write proof, `tree/src/predicates/quod_transaction_predicates.erl:42-57`. A failed or refused continuation commits nothing and is only counted, `tree/src/quod_runtime.erl:1463-1469` and `2164-2177`. So an event-only form can show Submitted and, if the continuation emits an event, Applied. It can never show "Needs attention" and it cannot bind a submitter identity. The state table at `:449-452` and example A's Applied promise at `:500-501` do not say this. Example C is correctly durable.
- **P1-4. Class resolution through `(quod:gui):Class` is a foreign call and must stay out of guards and selectors.** The shared `isa/2` closure routes foreign classes through `Ns::isa/2`, `tree/priv/ontologies/common_predicates.pl:154-158`, and that path carries no anchor. Reaction guards run in the events runner and resource selection in the resource worker, neither with a proof context. Schema and type validation belong in the signed open and submit proofs, and the descriptor compiler must resolve classes through the pinned `gui_vocabulary/2` anchor, not the bare closure.
- **P2-1. Revision coverage contradicts draft survival.** `:143-148` folds initial and context values into the revision, while `:337-339` promises drafts survive value refreshes. Split it into a schema revision checked at submit and a values token used only for display.
- **P2-2. Receiver scope is node-local and the plan over-promises distinguishability.** A control request is never forwarded, `tree/src/quod_client_goal_ingress.erl:329-330`, and presence is only observable where the socket terminates. The reason term must carry the scope it checked, and cross-node presence must be recorded as a routing gap rather than implied at `:248-254`.
- **P2-3. One `gui_open/2` hides two modes.** A direct form is a read-mode presentation with no durable row. A recoverable question needs the control lane. The plan should bind the mode to the form's declared completion promise and make a mode mismatch the same context violation the physics bridge raises.
- **P2-4. The `Submission` accessor is still unspecified** at `tree/doc/gui-plan.md:259-262`. Use the signed request's operation id. The proof context already holds it, `tree/src/quod_proof_context.erl:156-161` shows the pattern for expiry.
- **P2-5. Required policy grants are not named.** The human template admits only its own human, `tree/priv/ontologies/human_user_instance.pl:6-7`. Completion needs one narrow unlink grant for the responsible agent, keyed on the human's own reference row. Creation and submission need two narrow entries in the application ontology.
- **P2-6. Example A conflicts with live lobby data.** The founded sky stores brightness 120 at `tree/priv/ontologies/quod_lobby.pl:45`, the example stores permille 650 at `:497-499`. Choose one scale or declare the conversion.
- **P2-7. The replaced-path list is incomplete.** Besides `world.js` and `workspace-panel.js`, the ground `gui_view/2` forms at `tree/priv/ontologies/quod_gui.pl:27-44`, the eidolon workspace at `tree/priv/ontologies/quod_prolog_eidolons.pl:18-25`, `lobby_workspace/3` at `tree/priv/ontologies/lobby_instance.pl:73-78` and the lobby tests that read `gui_view/2` must move in the same slice. The view adapter must remain one process type that admits a second literal goal beside the one pinned at `tree/src/quod_client_simulation.erl:102-118`.
- **P3-1. Mockup drifts from section 8.** Cancel is separated by 36 units, not a 48 target width, `tree/doc/gui-use-cases.mockup.html:79`. Invalid input focuses one field and has no focusable summary, `:239-245`. Disabled controls show no reason, `:15`. "Needs attention" disables everything and offers no recovery action, `:202-206`. Opacity, opaque wells, keyboard placement, tab roving focus, live status and the decorative dial all match the spec.
- **P3-2. Budget ownership needs three named owners.** Pending questions per human is Prolog in the human ontology, checked by the link entry. Responder capacity is Prolog in the responder ontology, checked at open. Queue bounds at `tree/src/quod_runtime.erl:38-40` stay encoding limits and must surface at open as a reasoned busy refusal naming the agent.
- **P3-3. Agent re-ask semantics are unstated.** A work pass advances after a failed request and reselects only on a committed dependency change or a new incarnation, `tree/src/quod_runtime.erl:2179-2183` and `2255-2262`. A human who connects later does not wake a failed ask. That follows from the settled rule and belongs in sections 5 and 9C.

## Admission trace for a recoverable question

This is example C. Direct forms need none of it: their open is the HUD view's signed read, the responder availability check is a live bridge inside that read, and their submit is an ordinary execute carrying one event. Two principals act below, the responsible agent A hosted in ontology App, and the human H. The question id is the operation id of the agent's admission request, so no allocation scheme is added.

1. **HUD receiver exists.** H's browser opens the generalized view socket with a signed read into H's ontology. Ingress verifies the signature. The socket process registers `{gui_receiver, HRef, Incarnation}` through quod_reg and subscribes before snapshot, exactly as the simulation view does today. Principal: H. Nothing durable.
2. **Agent work selects the ask.** Shared behavior composes into App one `agent_work_goal/5` clause that selects `control(gui_open(review(W), _))` for each `gui_ask(review(W))` the author declares, with no existing question for that form, keyed by `term_digest/2` of the form. The author writes `gui_ask/1`, `gui_recipient/2`, `gui_responder/2`, `gui_form/3` and the continuation, nothing else. **Extension to existing owners:** the work projection and `quod_agent` accept a declared control mode, and a timed-out control request reports an uncertain error with no operation reference. This is the single semantic change.
3. **Admission request R1.** `quod_agent` signs R1 through the existing node read and submits it through `quod_client_goal_ingress:submit/2`. Principal: A. Target: App, which must be local. The proof is read-only with transients allowed. Committed checks: the form exists, `gui_recipient` yields H, `gui_responder` yields A, `agent_hosted/4` holds, the composed `react_on` and work clauses are present, the signing grant holds, policy capacity is not exceeded, no question exists for the form. Live query bridges: `gui_receiver(HRef, Scope, Receivers)` and `agent_available(A)`. Any miss is reasoned failure naming the resource and the scope. A new staging bridge stages `{gui_offer, Pid, Expected, Offer, Expiry}` where Expected binds HRef, incarnation and descriptor version, and Offer carries the id, form, H, A, schema revision and R1's exact bytes and signature. The answer binds `Question` to the id.
4. **Receiver acknowledgement.** `finalize_request_result` seals nothing and calls `release_transient`, which now has a second clause delivering the offer to the socket process with R1's deadline. The socket replies immediately: ok after pushing the offer frame, a definite refusal for a stale incarnation, unsupported version or full local offer table, and a lost reply becomes `{unknown, receiver_unavailable}`. **Caller result:** ok with `Question`, reasoned fail with nothing changed anywhere, or error meaning the receiver may have accepted. Nothing durable exists yet, so an error is not a hidden partial write.
5. **Durable creation R2, custody before dispatch.** The browser journals R2 in the existing operation journal and then signs `gui_accept(Bytes, Signature)` as H into App. The entry is admitted by one narrow `can_invoke` clause. A pure query bridge modelled on `signed_physics_request/3` verifies R1's signature against `agent_key(A, Key, active)`, its control mode, its target and its canonical goal, and exposes the id and expiry. The proof checks `current_principal(H)`, `gui_recipient` still names H, R2's own expiry is not later than the offer's, and no question exists for the id or the form. One `transaction/1` asserts the awaiting row in App, calls `HNs::gui_link(Id, App, Anchor, A)` in H's ontology where H is owner, and triggers `gui_question_opened(Id)`. Two writers form one existing atomic group. **Custody owner before dispatch:** the browser journal. An unknown result is resolved through the outcomes endpoint with the original bytes and is never resubmitted. A concurrent duplicate loses on the row conflict.
6. **Answer.** H signs `gui_submit(Id, Revision, Control, Fields)` into App. The narrow grant requires an awaiting row naming H. The proof validates every field against the committed schema, compares the revision, replaces awaiting with submitted values and triggers `gui_answered(Id)`. Single writer, OCC on the row.
7. **Continuation.** The composed `react_on(gui_answered(Id), gui_respond(Id)) :- me(A), gui_question(Id, _, _, A, _, submitted(_))` is the wake. The composed `agent_work_goal` selecting submitted rows is the durable path. `gui_respond/1` runs as A in a fresh proof: it instantiates the author's `gui_form/3` clause, binds the field variables from the submitted values, calls the continuation, retracts the row, calls `HNs::gui_unlink(Id)` under the narrow agent grant, and triggers `gui_question_closed(Id, Outcome)`. One atomic group. A duplicate wake finds no submitted row and fails plainly.
8. **Deaths and expiry.** Agent death after R1 loses only the reply. Socket death before the reply yields refusal or uncertainty with nothing durable. Socket death after the push leaves R2 in the browser journal. Agent death after R2 leaves the question for the next incarnation through agent work. The offer expires at its own expiry and R2 cannot outlive it. Row expiry after creation is Prolog policy.

Compliance check: R1 writes nothing and may consult live bridges. R2 and the submit consult none, so sealing admits their material diffs. The caller's deadline is never replaced. Unknown outcomes keep their exact reference. No question is ever created for an absent human. A question survives disconnect once R2 commits.

Not added: no owned-observation kind, no `prepare_signed_request` generalization, no custodied agent store, no second socket parser, no registry of agents, no retry timer. The `observed(...)` tier is not involved and I make no atomicity claim about delivery.
