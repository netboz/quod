# Native effect codec and receiver bridge

Independent source review; no Claude review. This extends the existing closed effect catalogue and journal. It does not yet expose gui_open or prove the complete atomic opening.

`present` has the fixed `gui_presentation` handler. Existing lifecycle descriptors/codecs are unchanged. The catalogue dispatches private encoding/decoding by validated operation; the journal uses that dispatcher instead of hardcoding lifecycle decoding. Private presentation bytes contain exact original request authentication, selected GUI identity/node, human, connection, receipt token and its original bound. Decoding is canonical and actor/target binding is checked before journal staging as well as release. No arbitrary callback or executable request is encoded as a new handler.

The new native module owns only that private codec and bounded release. The existing journal still owns custody, ordered release, crash recovery and disposal. Native release uses the exact signed execute request in a selected read-only scope. It activates the real accepted resource once. A lost/error response waits only for its original receipt expiry; no retry loop, new operation or material negative-outcome inference exists. Journal-worker recovery can observe the same idempotent receipt.

GUI's governed receiver predicates require an authenticated execute context inside a read-only proof of the GUI scope. Ordinary signed reads are refused. The ontology wrapper verifies the selected receiver and authored human pending allowance through the human's normal entry policy. Direct private-predicate invocation is refused by the GUI ACL. The native bridge accesses only the existing signed socket. It adds no question rows, status, queue, process or transport endpoint. Activation uses exact request-digest correlation, so a different caller request cannot consume a receipt; later selection changes do not revoke a previously accepted native opportunity.
