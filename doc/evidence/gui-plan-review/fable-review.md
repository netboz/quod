## Blockers

**B1. There is no receiver owner, and no push path to a human.** The plan hangs the "no connected human" failure and "acceptance before success" on an owner that does not exist ([reviewed-plan.md:341](/home/yan/src/quod/doc/evidence/gui-plan-review/reviewed-plan.md:341), [:350](/home/yan/src/quod/doc/evidence/gui-plan-review/reviewed-plan.md:350)). Every GUI read today is HTTP request/response through [signed-client.js:48](/home/yan/src/quod/client/src/signed-client.js:48). The auth session only proves key control ([quod_client_auth.erl:2](/home/yan/src/quod/src/quod_client_auth.erl:2)). The single live client attachment in the codebase is the physics WebSocket in [quod_client_simulation.erl:1](/home/yan/src/quod/src/quod_client_simulation.erl:1), which opens with a signed read and subscribes to runtime notices. Failure example: an agent's proof calls the motivating `text_box(my_text_box, Value)` against a human whose browser is open. Nothing on the server can learn that, and nothing can deliver the prompt, so the requirement at line 25 cannot be satisfied or even tested. Correction: generalize the simulation socket into one signed client view channel. The socket process registers itself under the human's agent reference in `quod_reg` (existing gproc facility). Opening a form is a read goal on that socket, so the socket is the receiver and the delivered reply is the acceptance. An agent-initiated prompt uses one `query`-class, `live_observation` predicate that looks up the registered socket, sends the ground projection and waits within the caller deadline. Absence fails, timeout errors, which is exactly the distinction the plan asks for at line 363. The live-observation classification in [quod_predicates.erl:283](/home/yan/src/quod/src/quod_predicates.erl:283) already vetoes sealing a material diff, which is what "opening writes nothing" needs. No new owner, no polling, no inventory.

**B2. The ontologies where forms naturally live host no agent, and a human instance cannot be hosted.** Reactions are matched only for hosted bindings of the owning ontology plus the node in its own scope ([quod_runtime.erl:1857](/home/yan/src/quod/src/quod_runtime.erl:1857)). Human-user ontologies are founded with `agent_key(me, Key, active)` and no `agent_host` row ([quod_signup.pl:109](/home/yan/src/quod/priv/ontologies/quod_signup.pl:109)). Personal lobbies host nothing, which the authority test states explicitly ([quod_reaction_authority_tests.erl:17](/home/yan/src/quod/test/quod_reaction_authority_tests.erl:17)). The human instance cannot become hosted later: `initialize_agent_host` requires no existing key ([agent_instance.pl:38](/home/yan/src/quod/priv/ontologies/agent_instance.pl:38)) and `agent_hosted` requires exactly one active key equal to the node-custodied host key ([agent_instance.pl:6](/home/yan/src/quod/priv/ontologies/agent_instance.pl:6)), so hosting `me` would revoke the browser key. Failure example: a settings form in a personal lobby commits `gui_submitted(...)`; dispatch finds zero candidates; the submission is "Submitted" forever. Correction: every GUI-bearing ontology needs a node-hosted application agent instance distinct from the human, with `can_invoke` for the handler goal and `can_request_agent_signature` for signing, exactly as the hosting tests set up ([quod_agent_hosting_tests.erl:498](/home/yan/src/quod/test/quod_agent_hosting_tests.erl:498)). The lobby demo in sequence step 5 needs a hosted lobby agent, which the plan must state.

**B3. "Admitted interaction" correlation cannot be matched by the runtime.** Reaction matching runs in a read-only `reaction` context over the committed snapshot ([quod_runtime_predicates.erl:216](/home/yan/src/quod/src/predicates/quod_runtime_predicates.erl:216)); the only bridges are `me/1`, request expiry and owner-supplied recovery or physics metadata. A volatile interaction handle is not visible there. The plan also forbids committing it ([:386](/home/yan/src/quod/doc/evidence/gui-plan-review/reviewed-plan.md:386), [:360](/home/yan/src/quod/doc/evidence/gui-plan-review/reviewed-plan.md:360)), so lines 267-273 ask for something no seam can provide. Correction: drop volatile correlation from matching. Correlate on committed data only: `FormRef`, the submitting principal from the signed request, and a committed `gui_responsible(FormRef, AgentRef)` fact that the guard checks with `me/1`. Two simultaneous questions are distinguished by their form instances, which the plan already requires to be distinct component instances.

**B4. The per-agent "bounded interaction context" and "capacity to own the interaction" are a shadow inventory.** Lines 275-281 would add transient per-interaction state to `quod_agent` or `quod_runtime`, which the plan itself and AGENTS.md forbid. Nothing in the proposed flow needs it once B1 and B3 are corrected: the client socket holds the open presentation, the agent holds nothing until the event arrives, and capacity is the existing request queue ([quod_runtime.erl:1983](/home/yan/src/quod/src/quod_runtime.erl:1983)). "Available agent with installed response handling" is checkable without new state: the `react_on` clause is a committed clause readable with `clause/2`, and the hosted process is observable through the exported `quod_runtime:agents/1` ([quod_runtime.erl:152](/home/yan/src/quod/src/quod_runtime.erl:152)).

## Design defects to fix before step 1

**D1. Forgery of the envelope is bounded by top-level goal discipline, not by a new ACL.** `trigger_event/1` is a `staging` predicate callable from any admitted proof ([quod_transaction_predicates.erl:42](/home/yan/src/quod/src/predicates/quod_transaction_predicates.erl:42)). `can_invoke/4` sees only the top-level goal, so the protection at line 290 is: admit `gui_submit/4`, never admit goals that embed caller-supplied callables. In owner-grants-all ontologies (human instance [human_user_instance.pl:6](/home/yan/src/quod/priv/ontologies/human_user_instance.pl:6), lobby [lobby_instance.pl:4](/home/yan/src/quod/priv/ontologies/lobby_instance.pl:4)) the owner can forge any event, which is acceptable because the handler runs as the hosted agent and rechecks domain preconditions. Consequence: the `Human` field is a claim, not evidence. Either remove it from the pattern, or carry the signed request bytes and have the handler verify them with `committed_operation_outcome/3`, which is proof-only and therefore usable in the handler but not in matching. The physics door path already does this ([quod_physics.pl:178](/home/yan/src/quod/priv/ontologies/quod_physics.pl:178)). Removal is the simpler choice.

**D2. "Do not broadcast private form data" is unachievable for committed events.** Subscribers receive every applied op of the source ([quod_runtime.erl:1299](/home/yan/src/quod/src/quod_runtime.erl:1299)), and the ledger is the public history. Privacy of submitted values is the owning ontology's hosting visibility, nothing finer. State that plainly at line 288.

**D3. Loss paths are real and only counted.** A submission refused with `busy` at 16 pending or 1 MiB, a hosted process killed by `stop_agents` on reconcile or replay ([quod_runtime.erl:1773](/home/yan/src/quod/src/quod_runtime.erl:1773)), or an overflow collapse all leave a committed event unhandled with only a counter incremented ([quod_runtime.erl:1344](/home/yan/src/quod/src/quod_runtime.erl:1344)). The plan's answer at line 320 is right. Make it concrete: the generic form is best-effort, and a form whose declared event has domain consequences must assert its pending state inside `gui_submit` and be drained by `agent_work_goal`, mirroring [fipa_request.pl:71](/home/yan/src/quod/priv/ontologies/fipa_request.pl:71).

**D4. Shared behaviour loading is founding-time source composition only.** The catalogue reads locally authored `react_on/2` clauses ([quod_runtime.erl:2653](/home/yan/src/quod/src/quod_runtime.erl:2653)); there is no inheritance of reactions. The only composition path is the `source(...)`/`terms(...)` option at founding ([quod_ontology.erl:340](/home/yan/src/quod/src/quod_ontology.erl:340)), the same way agent and FIPA behaviour reach instance ontologies. The "once per owning ontology" rule at line 252 therefore means one behaviour file composed at founding, and a `system_prolog_edit` transaction for existing ontologies. The whole shared behaviour is one clause plus one dispatcher, in the FIPA shape:

```prolog
react_on(gui_submitted(FormRef, Submission, Event), gui_handle(FormRef, Submission, Event)) :-
    me(Agent), gui_responsible(FormRef, Agent).

gui_handle(FormRef, Submission, Event) :-
    gui_event_goal(FormRef, Event, DesiredState),
    transaction(goal(DesiredState)).
```

The application supplies `gui_responsible/2` and `gui_event_goal/3`, as it supplies `fipa_request_allowed/3` and `fipa_request_goal/3` today.

**D5. Class discovery needs one forwarding clause.** `entity_eidolons/2` asks `class_eidolon/4` with direct classes only ([common_predicates.pl:14](/home/yan/src/quod/priv/ontologies/common_predicates.pl:14)); an application ontology holding `instance_of(Ns:text_box, name_input)` has no `class_eidolon` answer for GUI purposes. Add one forwarding clause in `common_predicates.pl` beside the prolog-source one at line 9, resolving the `quod:gui:eidolons` identity through root's catalogue. The `isa` closure across `::` at line 129 is unanchored; that is existing behaviour, note it rather than fix it here.

**D6. Delete the live-draft accessor option.** Line 334 keeps "live drafts" as a governed observation. Reading a browser draft from a proof is a proof worker waiting on a human, which line 379 and the requirements forbid. The accessor should read accepted domain values only.

**D7. Field validation and revision are mostly free.** `trigger_event` requires a ground term ([quod_diff.erl:196](/home/yan/src/quod/src/quod_diff.erl:196)), so a missing field leaves the template non-ground and the submission fails without extra schema code; only duplicate and unknown fields need explicit checks. For `Revision`, reuse the height the projection was read at (already returned to the client, [world.js:39](/home/yan/src/quod/client/src/world.js:39)) and let the OCC read set of `gui_submit` detect changed form facts. A separate revision fact is needless.

**D8. Replace, do not extend, the client role tables.** `proofForm`/`codeForm` enforce exact role sets ([world.js:105](/home/yan/src/quod/client/src/world.js:105)) and the panel throws on unknown kinds ([workspace-panel.js:157](/home/yan/src/quod/client/src/workspace-panel.js:157)). The generic descriptor path must supersede both, not sit beside them.

**D9. Translucency is not a mark problem.** The panel is a client-made plane with its own texture ([workspace-panel.js:17](/home/yan/src/quod/client/src/workspace-panel.js:17)), not a `mark/7`. Put opacity in the GUI appearance recipe vocabulary and leave `surface/5` alone, which is consistent with line 464.
