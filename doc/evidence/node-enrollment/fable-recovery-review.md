## Blockers

- **Definite refusals are treated as uncertain and strand the node forever.** `enrollment_result_kind` maps everything except committed and answered to `unresolved`, and `begin_node_enrollment` refuses a new request while any pending row exists. But the ingress already distinguishes nothing-sent from uncertain: `pre_send` and `{refused, _}` fall through every route to `signed_target_unavailable` ([quod_client_goal_ingress.erl:395](/home/yan/src/quod/src/quod_client_goal_ingress.erl:395)), only `{uncertain, _}` and router `unavailable` become a pending operation ([quod_client_goal_ingress.erl:440](/home/yan/src/quod/src/quod_client_goal_ingress.erl:440)), and `{normalized, {failed, _}}` is a completed proof that produced no transaction. On the live fleet the first enrollments will fail definitively: the serving validator has no allocation, so `node_initial_host` has no clause and the proof fails. With the current code that node writes a pending row, gets `failed`, marks itself `unresolved`, and can never enroll. Required: record the terminal result on the pending row and allow a fresh operation only for the three definite classes above, on the next readiness edge. Keep `operation_pending`, uncertain and worker-down as strictly unresolved. The same applies to the activation request in `activate_node`.
- **Lost pointer with a committed allocation is a dead end with no visible path.** `begin_enrollment` returns `node_identity_pointer_missing` and the manager logs once. Fail-closed is right under Yan's rule, but the status must say what the operator must do, and the retained ledger case should rebind from the committed allocation rather than refuse, since `allocated_identity` already yields the exact reference and `verify/2` proves it.
- **Pending pointer validation is too loose (known).** `valid_pointer_request` checks only signature and mode. The row must bind this node's key, the network identity, target `quod:node` at the catalogued anchor, and the exact goal shape; the activation row must additionally match the retained reference. `resume_enrollment` checks some of this at use, `activate_node` checks none of it.
- **The passing log is not clean.** The focused run reports 50 tests, 0 failures, but contains eight crash or error reports, including a namespace manager exiting on `system_catalogue_query_timeout` during cleanup. They look like negative-path fixtures, but the standing rule is to triage before trusting a run. Not a code finding; a gate finding.

## Custody, readiness, placement

- **Custody shape is right.** The row is written before dispatch, the same file owner serializes it, repeated same-blob writes are idempotent, and `resume_enrollment` resolves by the exact bytes and then reads the committed allocation instead of trusting the client reply. Worker death leaves the row and marks unresolved. The self case is recovered by the local effect journal as the comment says.
- **Readiness wake-ups are complete enough.** Root and quod:node replay and proof edges, catalogue changes, topology changes, the enrollment route wait, and `applied_live` touching the six policy functors all re-enter `enroll/0`. Two notes: the init-time trigger silently does nothing when `quod_client_auth` is not yet started (child order), which the app-level cast covers only at application start, not on a supervisor restart of the manager alone. And every allocation anywhere in the network wakes every unenrolled node's worker; cheap, but it should not log.
- **Remote placement boundary holds.** `pending_bootstrap` joins only through `prepare_host_join` with validator routes and never creates; the custodian advertises the identity as sole validator from its hosting row. The applicant stays an observer and activates through the forwarded `host_ontology` goal. The founder self case resolves through the topology edge after the async effect, which the automatic test exercises. One gap: a self-created identity whose effect never runs (journal `operator_error`) leaves the enrollment in `awaiting_route` on an identity nobody advertises. That state should surface the journal error, not wait.

## Provisioning of fresh seeds and the retained fleet

- **Delegation rows cannot live in the seed.** `ontology_creation_policy(quod:node, Anchor)` and `system_ontology(quod:node, Anchor)` need quod:node's genesis anchor, which does not exist when root is founded. They are post-founding root writes today, exactly like every catalogue row. The existing authorized path is an admitted node's native proof under root's `peer_admitted` clause or a root administrator's signed goal. That is how `quod:names` went live: founded through the root action, catalogue row committed afterwards.
- **The template belongs in quod:node's founding transaction, not duplicated.** Pass `terms([node_identity_template(Source)])` in the same `create_ontology` that founds quod:node from its source file, reading `node_execution.pl` once at the cascade step. Embedding the bytes in `quod_node.pl` would be a second copy of that file. For the retained fleet it is one authorized write into quod:node, and the new `enroll_node` rules reach retained quod:node only through the system-source edit path under root administration, as the contract already states.
- **Order on the live fleet.** Install template and delegations, then let each admitted validator self-enroll (local execution, executor equals applicant), then non-members. Until the serving validator is enrolled, forwarded enrollments fail definitively, which is why the first blocker matters.
