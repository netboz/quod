This is the unedited Fable review of tree-01. The operator-recovery suggestion based on checking absence and deleting custody is rejected: absence is not terminal evidence and cannot authorize retry. The later user permission to refound ledgers does not make uncertain-operation replay safe.

**Verdict for the frozen tree** (hashes match tree-01.json for all 19 files; the 115/0 integrated run precedes three later edits, so the full clean gates must re-cover them):

Correct and safe for what it tests. No security defect found. Prolog is the sole production recipe, the executor binding is sound, custody never resubmits an uncertain write, and the directory authority change is coherent. Three items in this scope should be fixed before commit, none of which changes the architecture. Retained-fleet migration is untested and is not approved by this review.

## Must fix in this scope

- **Dead founding fact.** `node_vocabulary(Namespace, Anchor)` is written into every new identity genesis by `node_identity_options` ([quod_node.pl](/home/yan/src/quod/priv/ontologies/quod_node.pl)) and referenced nowhere in src, priv or test. Once founded it is permanent in those histories. Remove it before any identity is founded.
- **Definite-refusal set is too narrow for local refusals.** `submit_retained` treats only `signed_target_unavailable` and a normalized `failed`/`fail` as definite ([quod_node_actor.erl](/home/yan/src/quod/src/quod_node_actor.erl) `submit_retained`). The ingress also returns, without sending anything, the local admission charge errors from `admit_forwarded_goal` ([quod_client_auth.erl:394](/home/yan/src/quod/src/quod_client_auth.erl:394)), the verification errors from `verify_request`, `wrong_target`, `{anchor_conflict, _}`, and the router's pre-send `busy` ([quod_client_goal_router.erl:305](/home/yan/src/quod/src/quod_client_goal_router.erl:305)). All of these become `{submitted, unresolved}` and the pending row then blocks any new request forever. That is a permanent strand after a never-sent request, which the strict rule does not require. Post-send ambiguity is confined to `{normalized, {pending, _}}` ([quod_client_goal_ingress.erl:440](/home/yan/src/quod/src/quod_client_goal_ingress.erl:440)); everything the ingress returns as `{error, _}` from `submit/2` was never admitted. Classify those as definite, keep `pending` and worker death unresolved. You are right to verify independently that no post-custody error escapes `target_execute` as a bare `{error, _}` before adopting a blanket rule; an explicit allowlist of the pre-send error atoms is the safe form if that proof is not clean.
- **Terminal negative outcomes are treated as absence.** `resume_allocation` discards the `resolve_operation` result. A resolved `rejected` or `aborted` outcome (atomic group abort at Vote, or an OCC conflict) is a certified terminal answer about the exact operation, not absence, yet the node stays `unresolved`. Handle the terminal negative outcome as a definite refusal; leave `operation_pending` unresolved.

Crash before send, after commit, after allocation and known refusal are tested through the real owner, and the unchanged-restart test proves no spawn, no commit and no pointer write. The opaque reserved-term test covers the ordering. - **Expiry retraction, for the archive.** My earlier claim that absence after request expiry plus proof timeout plus skew is terminal was false and is withdrawn. Custody deadlines are arrival plus relay timeout ([quod_simplex.erl:7889](/home/yan/src/quod/src/quod_simplex.erl:7889)), journal-restored and dormant rows never expire ([quod_simplex.erl:3328](/home/yan/src/quod/src/quod_simplex.erl:3328), [quod_simplex.erl:8398](/home/yan/src/quod/src/quod_simplex.erl:8398)), and commit validation has no expiry check. Expiry never licenses a resend; the tree correctly treats it that way.

## Acceptance gaps and rollout facts

- **Fleet topology consequence.** On the live fleet the non-founder nodes are quod:node observers, so their `enroll_node` goal is forwarded to the founder, the root scope is co-hosted there, and the founder becomes custodian of every node identity. That is correct per the contract but concentrates control and write liveness of all identities on one node. If that is not intended, admit the fleet to quod:node's committee before enabling the delegation, so each node executes locally and self-custodies. Yan's call.
- **Unspecified operator recovery.** The contract promises explicit recovery for an unresolved pre-admission request but gives no procedure. State it: verify no allocation exists for the key, then remove the pending row, accepting that a custodied transaction could still commit and would then be reconciled by the allocation guard.
- **Untested paths.** `signed_target_unavailable` refusal followed by route wait and re-enrollment; `node_enrollment_policy_mismatch`; the existing-fleet-validator case (root validator, quod:node observer), which the contract names as an acceptance path; custodian crash between group commit and effect execution with the applicant parked on the route; retained migration end to end.
- **Consultative.** Control peers emit an empty root withdrawal on every renewal forever; non-control nodes mid-enrollment log `advertisement_author_unavailable` every 10 s; unresolved nodes re-run resolution on every topology and reconcile edge rather than only on their dependencies.
