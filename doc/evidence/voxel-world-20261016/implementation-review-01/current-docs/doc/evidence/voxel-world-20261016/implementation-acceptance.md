# Smooth terrain implementation evidence

This is an implementation checkpoint, not approval to commit, deploy, found a
world or mutate a live ontology. Cubic terrain and flying-lobby integration are
deferred by the user. The full plan remains in progress.

## Delivered in source

- Composable Prolog world definitions, ownership policy, current sparse edits,
  atomic digging/painting, safe regeneration and removal. Worlds reuse the
  existing physical body allocator and transaction/recovery framework.
- Versioned deterministic integer fields, corrected MC33 surfaces, caves,
  biome blending, and material palettes through the shared compiled predicate
  and existing native physics library.
- Native constituent colliders, whole-body coverage/solid checks and local
  origin shifts. Missing terrain pauses movement without losing the original
  input, deadline or simulation incarnation.
- Movement-driven bounded residency, separate visual and physical consumers,
  signed manifests with one delivery credit, retained render models, authored
  viewing distance and fog. Exploration adds no durable world facts.
- Existing GUI question/responder forms for generation, digging and viewing
  distance; class-selected terrain appearance through space/Eidolon/model
  composition; ordinary verified PBR texture resources.
- A Babylon geometry preview generated by production sampling/editing and
  rendered by the existing model/resource owners. It is a local inspection
  fixture, not a live authenticated world session.

## Remaining scope and limits

- Nearby/travel-direction ordering is implemented in the existing worker
  and signed delivery owner and passes the full campaign. The worker still
  admits and publishes a complete bounded window; it never exposes an
  incomplete window as ready. Partial visibility and distance LOD are not
  provided.
- The normal browser opens the personal lobby. These ontology/forms bundles
  are composable through existing source/console facilities; a user-facing
  world factory/chooser is not installed or implemented. No live world was
  created during this work.
- The first GUI exposes three landscape presets and shared parameters; the
  full per-biome catalogue editor and pointer-driven sculpting are not present.
  Pointer-driven sculpting already requires a separate capability decision in
  the plan. Sphere digging uses the existing submitted form.
- The surface profile uses flat face normals, categorical material boundaries
  and dominant-axis UV projection. Texture seams can appear where the dominant
  axis changes. Minecraft texture packs have not been inspected or imported.
- Full live multi-node refresh/control-interruption measurements, collider
  fan-out measurements and cross-platform numerical receipts have not been
  established by these local tests. The implementation must not be described
  as satisfying every acceptance item in the broader plan.
