## Fable review of `clean-integration-02/tree`

Verdict: consultative, not a deployment approval. The frozen candidate holds its architectural line: worlds compose into the existing user-owned lobby, the client reuses one initializer and one journal identity, and material admission is Prolog policy read through the existing proof owners with no second executor, split transition or enlarged transport. I found no defect in consensus, signature, custody or OCC contracts. I did find one functional defect in the new domain, one operational-safety gap in the admission design, one trust-model regression worth a decision, and several smaller client and cleanup issues. Full gates were still running when I read the receipts; nothing below claims a gate pass.

All paths are relative to `/home/yan/src/quod/_build/world-library-20261016/clean-integration-02/tree` unless marked review-01.

### Review-01 frozen defect, confirmed, and the reported correction

Confirmed in the review-01 freeze: `review-01/tree/priv/ontologies/lobby_worlds.pl:116` passed the literal `vector(-1,Bottom,-1)` to the sampler. The frozen erlog parser builds terms only from positive number tokens and treats `-` as a prefix operator (`_build/default/lib/erlog/src/erlog_parse.erl:66` and `:270`), so a `-1` in a data position is the compound `'-'(1)`, which `quod_voxel:sample/4` rejects as `invalid_voxel_field`. The retained diagnostic shows the same shape for the `-16000` fact argument (`doc/evidence/world-library-20261016/spawn-diagnosis-01/run.log:123`). In that freeze no world could be created for any recipe.

Parent-reported correction, verified in this freeze: `priv/ontologies/lobby_worlds.pl:115-117` now evaluates `Outside is -1` once and uses it for both the vector and the sentinel. The 72-combination spawn test exists at `test/quod_voxel_world_tests.erl:33-58`; the passing receipt is the parent's (`spawn-02`), not mine.

### Confirmed defects

1. **Terrain tools form cannot compile for any library world.** `priv/ontologies/lobby_worlds.pl:170` declares `range(-1000000,1000000,100)` as data, so the same parser rule yields `range('-'(1000000),1000000,100)`. The GUI vocabulary requires `integer(Min)` (`priv/ontologies/quod_gui.pl:226-227`), so `gui_tree_schema` fails, `gui_compile(voxel_excavation(W),...)` fails, and the library's `edit` action (`world_library_open(edit(W),_)`, `lobby_worlds.pl:46-49`) is refused for every owned world. No frozen test reaches this: the terrain-core fixture supplies its brush ranges as Erlang terms (`test/quod_gui_examples_tests.erl:222`), and the browser record did not dig. Same class as the spawn defect; evaluate the bound with `is` or, more durably, decide whether the parser should produce ISO negative numeric literals so this class disappears everywhere (`quod_lobby.pl` carries many such data literals that currently survive only because they are evaluated or re-parsed downstream).

2. **A bad material override locks an ontology out permanently.** Every sealed plan first selects policy from the target's pinned committed state (`src/quod_dtx.erl:190-205`), and selection fails closed on a malformed, duplicate or unknown-resource override (`src/quod_material_admission.erl:38-49`). The write that would correct the override is itself a plan in that ontology, so it is refused too. A too-tight numeric override has the same effect: any retract has symbols and one operation, so `material_limit_override(plan, symbols, 0)` or `(plan, operations, 0)` is unrecoverable. Overrides are ordinary owner-writable facts (`priv/ontologies/material_policy.pl:1-9`), and a lobby owner has unrestricted invoke rights (`priv/ontologies/lobby_instance.pl:4`). The fail-closed choice is right for reading policy; it is wrong for admitting the write that creates the policy. Smallest correction: in `seal_session_checked`, when the diff touches `material_limit_override/3`, evaluate the policy over the staged view and refuse the plan unless the resulting policy is valid and still admits a single-operation retract of that override. Root's `founding` overrides are recoverable through root's own plan lane, so only `plan` overrides need the guard.

3. **Library controller swallows resolution outcomes.** `client/src/space-library.js:112-116` discards the result vector of `resolveSignedOperations`, so a failed outcome endpoint, a non-terminal reply or a `terminal` callback that threw (for example a committed `create` whose reply lacks `Question`, `:99-103`) leaves the journal row in place and the status text cycling between "saved operation" messages with no reason. `client/src/question-controller.js` already reports these cases; mirror it. Carried over from review-01; unchanged in this freeze.

### Risks and design gaps, distinct from defects

- **Admission is proposer-only; validators never re-check usage against policy.** `quod_material_admission:check/3` is called only at seal (`src/quod_dtx.erl:322`) and founding (`src/quod_ontology.erl:830`, `:879`). Commit validation only decodes material (`src/quod_commit_validation.erl:758-759`). With the fixed 512 decode quota removed (`src/quod_wire_term.erl:200-212`), an honest node materializing a relayed transaction from a faulty admitted proposer is bounded only by the block byte bound and the atom-table headroom margin (`include/quod_vm_limits.hrl:6`). At roughly twelve canonical bytes per distinct symbol that is on the order of tens of thousands of permanent atoms per transaction, durable in history on every node. This is inside the BFT trust model and was authorized as "historical decoding independent of today's policy", but live relay of a fresh transaction is not history. Recommended decision: validators recompute limits at the plan's base height (the policy reads are already in the sealed read set) and compare with the same usage measurement before materializing. That keeps history replay free of today's policy while making admission a consensus check.
- **Capacity derivation is exact to the byte on the history page.** Two maximal blocks plus the 64-signature allowance equal 921,600 bytes, the page limit itself (`include/quod_ingress_limits.hrl:16-20`, `include/quod_transport_limits.hrl:8`). Correct by construction and checked by the maximal two-block test, but there is zero margin for any future page metadata. Derived values for the parent's record:

  | Bound | Value (bytes) |
  | --- | --- |
  | `MAX_BLOCK_BYTES` | 456,832 (was 262,144) |
  | Canonical transaction | 456,689 |
  | DTX body | 424,064 |
  | Scope envelope | 1,012,977 of a 1,048,576 frame |

  No carrier constant was raised. Blocks are now about 1.74 times larger, so worst-case ingress and relay memory per block grows by the same factor under the unchanged 512 ingress population bound.
- **Spatial view refusal reaches the user as prose composed in the physics worker** (`src/quod_physics.erl:941-951`, forwarded by `src/quod_client_view.erl:587`). It names the resource, amount and allowance as required, and releases only that viewer (`:897`). A structured term with client-side wording would localize better; not a defect.
- **Appearance and scene changes now retire the space and close the open workspace** (`ui/src/World.tsx:135`, `:497`, `:501`). Question drafts survive because their controllers are retained separately; the console or library panel does not. Intentional per the parent's note, but it is a behaviour change from the pre-library shell.
- **Initial chunk at a surface boundary** (`priv/ontologies/lobby_worlds.pl:164-165`): when the surface sits exactly on a chunk boundary the selected chunk lies above the ground; mechanical demand repairs coverage, so this is only a startup hint imprecision.
- **Repeated-operation cost:** each seal and each founding now runs one extra read-only proof session with a private read-set table (`src/quod_material_admission.erl:27-29`, `src/quod_erlog_db_local_prove.erl:177`), and `admit_core` decodes the material once more to count symbols (`src/quod_dtx.erl:316-320`). Bounded and small, but it is per write.
- **Leftover:** `src/quod_dtx.erl:528` still types `too_many_new_atoms`, which `materialize_symbols` can no longer return.

### Priority 1: composition, completion, identity

Verified by reading. Creation is one `gui_complete` continuation: identity from the active question occurrence (`lobby_worlds.pl:81-84`), exact anchored form (`:83`), library allowance at the policy owner (`:85-86`), name drawn once and saved as an attribute (`:87`, `:101-107`), renderer limits read from the pinned rendering vocabulary (`:136-144`), view scaled with spacing (`:148-150`), then `voxel_create` and presentation validation inside the same transaction (`:98`). Duplicate labels cannot collide because identity is the digest of the occurrence. Each world has its own authority and pilot with per-world signing and store grants (`lobby_instance.pl:63-87`, `lobby_worlds.pl:152-159`). The human cannot invoke creation directly: the policy binds the actor to the responder (`lobby_worlds.pl:51-52`), and the fixture asserts the forged call fails (`test/quod_gui_examples_tests.erl:38-39`). The landscape pool is original data by inspection (`priv/ontologies/quod_names.pl:404-419`). Native admission still owns installed clearance; the pure candidate only proves enclosure of the capsule's lattice corners.

### Priority 2: client initializer, controller, selection

One journal identity per setup (`client/src/space-entry.js:23-43`), cancellation only before the journal row (`client/src/signed-client.js:49-57`), no resubmission (outcomes endpoint only, `space-library.js:115`). Late results after close retain the journal row rather than deleting it (`space-library.js:96-98`), which is the conservative side. Stale views are retired on scene, mode, identity and space changes, and an unchanged selection is kept alive (`ui/src/World.tsx:52-63`, `:204-214`). Return stays available while a destination loads. The desktop form now renders the catalogue selection (`ui/src/GuiForm.tsx:119`, `:164`), which closes my review-01 finding. Fresh human source composition lists the HUD file (`priv/ontologies/quod_signup.pl:105-121`, `doc/gui-examples.md`); existing live ontologies still need an explicit source installation, which the deployment reset makes moot for this release. The Cowboy fix uses a labelled OTP call with the original deadline (`src/quod_client_view.erl:27-38`, `:561-566`) and is exercised through a real Cowboy loop in `test/quod_client_tests.erl:6-38`.

### Priority 3: material admission

Policy comes from the committed state, never the staged write (`src/quod_dtx.erl:195-199`, `src/predicates/quod_ontology_predicates.erl:126-140`); its reads join the OCC set, and the tests cover a staged self-grant and a concurrent policy change (`test/quod_material_admission_tests.erl:43-50`, `:72-93`). Founding counts raw symbols before any atom is allocated (`src/quod_ontology.erl:824-840`) and then measures the compiled canonical diff (`:875-881`). Plans measure the complete envelope with a signature placeholder of the real width (`src/quod_dtx.erl:309-320`). Decoding accepted history applies only alphabet, depth and VM-headroom checks (`src/quod_wire_term.erl:200-212`, `:358`); the client goal parser keeps its own 512 symbol quota (`:217-227`). Cold vocabulary quotas and raw ETF size guards are gone with no leftover callers. The remaining concern is the validator-side gap described above.

### Priority 4: terrain integration corrections

The sparse override lookup reads the relation once and keeps absence as a dependency (`priv/ontologies/voxel_world.pl:178-188`); the test checks the dependency key, neighbour coverage and the ambiguity refusal (`test/quod_voxel_world_tests.erl:12-31`). View and padding scale with spacing, and the form range follows (`lobby_worlds.pl:148-150`, `:166-169`). An over-budget view is refused with its resource and allowance and only that viewer is cleared (`src/quod_physics.erl:941-951`, `:897`); the owner-level test covers refusal and a smaller reentry (`test/quod_gui_examples_tests.erl:117-124`). The runtime was not changed in this scope: an interrupted selection keeps a conservative dependency until the next committed change (`src/quod_runtime.erl:1156-1170`), and an unavailable world keeps its exact owner suspended rather than deleted (`:282-296`). No new defect found there.
