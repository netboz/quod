Supplement to the frozen04 validation report. The defect the parent reports is outside the corrections patch but inside the tree I validated, so it changes the report's remaining-defects section; everything else stands.

**Confirmed from the frozen04 source.** A world owner that enters the `coverage` phase for a pending collision query has exactly one exit: a later installation with changed colliders. `installed_frame` keeps the phase when nothing waits and nothing changed (`src/quod_physics.erl:452-459`, the `{_,_,coverage,0,_} -> Controlled` clause), and `hold_terrain` pauses stepping until then (`:684`). When the viewer unwatches during that wait, `clear_viewer` marks the input not pending and only refreshes demand (`:1010-1020`); it never asks whether the coverage wait is still justified. The shrunken demand reaches the runtime (`src/quod_runtime.erl:691-700`), which reselects; because the required chunks are already installed, `install_physics` sees an unchanged spec and re-notifies the owner only through `needs_reconciliation`, clearing that flag as it does (`:3240-3252`, `:3277`). The owner then re-installs with zero changes and stays in `coverage`. That is the exact state both diagnostics retain: phase `coverage`, `navigation_ready` false, only the current body's chunk installed, runtime `needs_reconciliation` false and no source waits (`doc/evidence/world-library-20261016/terrain-disconnect-diagnostic-01/run.log:43-52`, `-02/run.log:113`). The second diagnostic waits on real notifications for fifteen seconds, so this is a liveness defect, not an early assertion.

**Classification.** Pre-existing in the coverage-wait design rather than introduced by the 04 patch: before the patch the same unwatch left the owner in `coverage` with zero changes too, only with the query's coverage already evicted. The patch's retained coverage made the disconnect case testable and exposed it. Consequence for users: a world left during a pending query stays paused and reports unavailable on re-entry until some unrelated selection change installs new colliders. No data, custody or safety impact. My correction inspection covered when retained coverage ends, not whether the owner re-evaluates its wait when the consumer leaves; I missed the resumption side and record that here.

**Effect on the verdict.** Frozen04 now carries one remaining confirmed defect, so it is not a release candidate on its own, which matches the parent's stop at the current gate. The parent's described correction, cancelling the input through the shared helper and rechecking native coverage once when no insertion is unfinished and the navigation source is current, addresses the right seam without a timer or retry; I have not read it and it needs its own freeze and validation.
